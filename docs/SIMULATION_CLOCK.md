# 描画速度とシミュレーションの時計

描画が遅いときに時間を1フレーム60msに切り詰める処理を廃止し、実経過時間を120Hzの固定刻みで処理する。海、船、飛行、衝突、レースを同じtickで進め、衝突・完走でそのtickから先を止める。描画はフレームに1回のまま。海のFFTは既存の最大30Hz更新を維持する。

通常の遅延は蓄積する。1フレームの処理上限は600tick（5秒分）で、残りは持ち越す。未処理の時間と新しい経過時間の合計が10秒を超えた場合はフライトを明示的に止め、位置や船だけを先に進めない。起動素材の読み込み後、開始、再開、メニュー、設定・ヘルプの開閉、タブの切替、画面の離脱、WebGL状態喪失で時計をリセットする。Xboxの同期的なリセット・再開を考慮し、入力のpoll後に基準時刻を採取する。

海の形状は30Hzで更新されるため、船の離陸地点の速度を1/120秒の位置差から計算すると、海面更新直後だけ波による速度が約4〜5倍になる。海面の完全な更新間隔で離陸地点を標本化して速度を計算し、間のtickでは保持する。時刻の巻き戻し、0.2秒以上の時刻ジャンプ、海況変更で履歴を破棄する。同じ時刻に海況を変えた場合も船を新しい海面に合わせて更新する。

修正前の640×480 SwiftShaderでは、約640ms/フレームに対して世界が60msずつしか進まなかった。RTX4050で2秒分240tickを計測した3回の処理時間は約1187/1061/1057msで、大半が海のFFTだった。最大batchの応答性と持続性能の改善は残る。時計修正によるFPS改善は主張しない。画質、波の解像度、船・地形の形状、コントローラーの軸割り当ては変更しない。

時計修正後の同じ208draw/6,227,181三角形のSwiftShader計測では、最後の間隔が実時間1.2143秒に対し世界1.225秒になった。採取時刻は描画とCPU処理の前後でずれるため、瞬間の完全一致やFPS改善の証拠として扱わない。60msの時間欠落が解消されたことと、固定刻みの結果は別々に検証する。

5件の時計単体回帰は、60FPS/5FPS/不規則なフレーム列の飛行結果・船姿勢・レース経過の一致、残時間の保持、時計リセット、長時間遅延の停止、衝突・完走の中断を検証する。ブラウザ回帰は実際に350msと10.1秒の主スレッド遅延を発生させ、海・船・飛行のtick一致、位置を飛ばさない停止、再開を確認する。レース開始の0秒リセットは実際のStartボタンの同期クリック直後に確認し、18ゲートの実際のRAF通過と既存期限は維持する。

離陸速度の回帰は実際の船と海を24tick進め、海面更新の前後の速度、更新の間の保持、時刻巻き戻し、同時刻の海況変更と新しい水面への追従を確認する。

時計APIの仕様を確認した資料：[requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)、[performance.now](https://developer.mozilla.org/en-US/docs/Web/API/Performance/now)。requestAnimationFrameの時刻は同一フレーム内のコールバック間で共有されるため、入力処理が時計をリセットした後の採取にはperformance.nowを使用する。

実機Xbox・USB送信機、他GPU/ブラウザ、長いプレイセッションの受入は未確認。公開CIと本番の確認結果はPRに記録する。

送信機の入力回帰は、実際の最初の飛行描画を通常停止中に完了し、時刻0・カメラ一致と100万超の描画三角形を確認する。キーボード回帰と同じく、ソフトウェア描画ではその後の入力・物理検証から全景の描画負荷を分離する。実際のRAF、時計、波、船、接触、送信機のpollとDOM操作は維持し、nativeモードは飛行中も全景を描く。このソフトウェア検証は画質や持続FPSの合格ではない。

移動の各20秒期限は維持する。10秒を超える遅延の保護停止だけを識別し、実際のスロットル低下と通常の再開操作を期限内で実行する。衝突や別の停止、時間切れを合格にしない。実際の10.1秒停止からの離陸成功と、繰り返し停止して進まない場合の元の20秒期限での拒否を別々に確認した。製品の時計・保護停止・アーム条件は変更していない。
